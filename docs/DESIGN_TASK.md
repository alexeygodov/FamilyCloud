# Задача: переработать интерфейс FamilyCloud по ТЗ дизайна

Для агента-исполнителя. Работай только в `cloud-app/`.

## Прочитай перед началом

1. `cloud-app/AGENTS.md` — правила проекта (стек, секреты, коммиты, CI).
2. `cloud-app/SPEC.md` — функциональные требования. Их не менять и не расширять.
3. `cloud-app/docs/DESIGN.md` — ревью и ТЗ по дизайну. **Это основной документ задачи.** Здесь — только порядок, решения и проверка.
4. Скилл `cloud-app/.agents/skills/modern-jetpack-compose/SKILL.md` и его `references/` (design, state, navigation, accessibility).

## Цель

Сделать интерфейс удобным и аккуратным по `DESIGN.md`, части 2 и 3, этапы D1–D8. Логику WebDAV, синхронизации и обновления не трогать, кроме того, что нужно для показа состояния в UI (например, прогресс выгрузки на экране).

## Порядок работы

Этапы строго по порядку. После каждого этапа:

```
./gradlew testDebugUnitTest lintDebug assembleDebug
```

Все три зелёные — коммит этапа (сообщения по-английски, повелительное наклонение, например `Handle system back in file browser`). **Не пушить** без согласия пользователя. Не начинать следующий этап при красной сборке.

### D0. Подготовка структуры (без изменения поведения)

- Разнести `ui/Screens.kt` (~1000 строк) и `ui/ViewModels.kt` по пакетам: `ui/browser/`, `ui/sync/`, `ui/settings/`, `ui/viewer/`, `ui/components/`, `ui/theme/` (`DESIGN.md` 2.16).
- Для каждого экрана: `XxxRoute` (ViewModel, `collectAsStateWithLifecycle`, интенты) и `XxxScreen` (только состояние и лямбды).
- Отдельный коммит, поведение не меняется. Проверка — сборка и lint.

### D1. Ошибки навигации (`DESIGN.md` часть 1, P0)

- N1, N2: `BackHandler` в экране файлов: снять выделение → папка вверх → выход. Выключен в корне без выделения.
- N3: подключение из файлов — со стрелкой «Назад»; после успеха `popBackStack()` и обновление списка, без второго экрана файлов. При первом запуске — старт без стрелки, переход в файлы с удалением подключения из стека (как сейчас). Сейчас: `ui/AppNav.kt`, маршрут `connection`.
- N4: подтверждение «Убрать альбом» (текст в `DESIGN.md` 2.8).
- N5: шапка и нижняя панель выбора папки (2.6). Режим (переместить, копировать, папка для альбома) передать аргументом маршрута `picker`. Кнопка «сюда» неактивна для той же папки и для папки внутри перемещаемой.

### D2. Тема и ресурсы (2.2)

- `ui/theme/Color.kt`: светлая и тёмная схемы из seed `#1565C0` (значения из Material Theme Builder, вписать вручную). Dynamic Color на Android 12+ оставить.
- `ui/theme/Dimens.kt` и замена магических `dp` в экранах.
- `res/values/themes.xml` и `res/values-night/themes.xml`: фон окна в цвет поверхности.
- Adaptive icon: `mipmap-anydpi-v26/ic_launcher.xml` (background, foreground, monochrome), манифест на `@mipmap/ic_launcher`. minSdk 26, поэтому запасная растровая иконка не нужна; старый `drawable/ic_launcher.xml` удалить, если на него больше нет ссылок.

### D3. Общие компоненты (2.4)

`ui/components/`: `EmptyState`, `ErrorState`, `Notice` (с запоминанием закрытия в DataStore через существующий `SettingsRepository`), `LoadingList`, `FileGlyph`, `TransferBar`. Для каждого `@Preview` в светлой и тёмной теме.

`TransferBar` берёт прогресс из `WorkManager.getWorkInfosForUniqueWorkFlow("uploads")` / `"sync-now"` (progress data). Если воркеры сейчас не публикуют прогресс через `setProgress`, добавить это в `sync/Workers.kt` рядом с уведомлением, не меняя логику выгрузки.

### D4. Экран файлов (2.5)

Шапка и меню «⋮», хлебные крошки с `Home`, сортировка в `ModalBottomSheet`, строка списка, мультивыбор с галочками и «Выбрать все», один `ExtendedFloatingActionButton` с листом действий, диалоги с валидацией под полем, snackbar после действий. Убрать дубль ошибки (`message` + `failure` в `BrowserViewModel.refresh`): при пустом списке — `ErrorState`, при непустом — snackbar.

### D5. Подключение и обновление (2.7, 2.11)

Поля с иконками и `ImeAction`, глаз для пароля, `Switch` HTTP с условной плашкой, ошибка в `Notice`, «Подробности» свёрнуто, кнопка с индикатором. Диалог обновления короче, прогресс в МБ и процентах, шаг разрешения на установку.

### D6. Синхронизация (2.8, 2.12)

Блок статуса сверху (берёт состояние из WorkInfo и пар), плашки по важности, карточки пар с `FilterChip`, меню карточки, FAB «Добавить альбом» и мастер из трёх шагов. Для превью и числа файлов альбома расширить `MediaScanner.albums()` (последний `_ID` и количество) — запрос вне главного потока. Уведомления: текст с именем файла, итоговое уведомление, нажатие открывает приложение.

### D7. Просмотр фото и видео (2.9, 2.10)

Чёрный фон, полноэкранный режим по нажатию, счётчик «N из M», нижняя панель «Скачать / Сведения / Удалить», индикатор загрузки и ошибка. Видео без Scaffold-шапки, оверлей, ландшафт по кнопке, ошибка с «Повторить» и «Скачать».

### D8. Тексты и доступность (2.13, 2.14)

`plurals` для счётчиков, формат дат «сегодня / вчера / дата», сокращённые тексты ошибок, удаление неиспользуемых строк, `contentDescription`, семантика строки списка, проверка шрифта 200%.

## Ограничения

- Не менять поведение WebDAV, `UploadEngine`, `SyncRepository`, `UpdateRepository`, кроме публикации прогресса (D3) и данных альбомов (D6).
- Не трогать `docs/REVIEW.md`, `docs/AUTH_DEBUG.md`, `SPEC.md`. В `DESIGN.md` можно только отмечать выполненное.
- Все строки — в `strings.xml`. Никаких `Color(0x…)` и `.sp` вне `ui/theme/`.
- Никаких реальных адресов, логинов и паролей в превью и тестах: только `https://example.keenetic.link/webdav/`, `user`.
- Существующие юнит-тесты должны оставаться зелёными; удалять их нельзя.
