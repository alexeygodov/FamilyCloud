# Заметки о сервере

Реальный роутер Keenetic этой сборкой не проверялся. Клиент следует RFC 4918 так, как описано в `SPEC.md`. Поведение MOVE, COPY, Overwrite и лимита размера файла на конкретной прошивке неизвестно и не подменяется догадкой.

Проверьте на своём Keenetic:

- PROPFIND с Depth 0 и Depth 1 отвечает 207, а href бывает абсолютным, относительным и с префиксом `/webdav/`.
- Папки в href заканчиваются слэшем.
- MKCOL создаёт папку (201 или 204).
- PUT большого файла принимает известный `Content-Length` и не обрывается на файле около 1 ГБ.
- Загрузка идёт как `имя.part.ext`, затем MOVE в окончательное имя. Destination — абсолютный URL, Overwrite по умолчанию `F`.
- MOVE и COPY с Overwrite `F` не затирают существующий файл и возвращают конфликт, если цель занята.
- DELETE удаляет только то, что вы удалили в интерфейсе, и собственные `.part` приложения.
- Повторная выгрузка файла того же размера не создаёт дубликат. Другой размер получает суффикс ` (1)`, ` (2)`.
- HTTP используется только если в приложении включено «Разрешить HTTP». Иначе адрес должен быть `https://`.

Пример адреса в документации: `https://example.keenetic.link/webdav/`.

Клиент ходит на WebDAV только по HTTP/1.1. На HTTP/2 Keenetic отвечает 401 на PROPFIND, хотя тот же пароль по HTTP/1.1 принимается. Незавершённая выгрузка называется `имя.part.расширение`, затем MOVE в окончательное имя. `displayname` из PROPFIND показывается в списке, а путь и конфликт имён считаются по `href`.

Когда появляется файл на выгрузку, приложение пробует показать уведомление и в фоне. На Android 12+ это удаётся, если приложение исключено из оптимизации батареи (экран синхронизации это предлагает). Иначе система запрещает службу, работа обрывается примерно через 10 минут и большой файл начинается заново: его надёжнее отправить кнопкой «Синхронизировать сейчас». Кнопка «Отмена» есть только у этой кнопки и у выгрузки из интерфейса. Докачки нет.
