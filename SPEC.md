# ТЗ: Android-клиент WebDAV «FamilyCloud»

Правила работы агента — в `AGENTS.md`. Этот файл — требования.

## 1. Цель

Простое Android-приложение:

- файловый менеджер для WebDAV-сервера (роутер Keenetic) по аналогии с Яндекс/Google Диском;
- автоматическая выгрузка фото и видео из выбранных альбомов телефона в выбранные папки сервера.

Единственная настройка подключения — параметры WebDAV. Интерфейс на русском.

## 2. Технологии (зафиксировано)

- Kotlin, Jetpack Compose, Material 3, одна Activity, Navigation Compose.
- minSdk 26, targetSdk — актуальный стабильный. Package: `app.familycloud`.
- MVVM, Coroutines/Flow. DI: Hilt (допустим ручной DI).
- Сеть: **OkHttp** и свой тонкий WebDAV-клиент. Методы `PROPFIND` (Depth 0/1), `MKCOL`, `PUT`,
  `GET`, `MOVE`, `COPY`, `DELETE`. XML — `XmlPullParser`. Готовые WebDAV-библиотеки не использовать.
- БД: Room. Настройки: DataStore. Пароль: Android Keystore (EncryptedSharedPreferences или аналог).
- Фон: WorkManager. Картинки: Coil с OkHttp-клиентом с Basic-авторизацией.
- Видео: Media3 ExoPlayer, источник с заголовком `Authorization`.
- Зависимости только через `gradle/libs.versions.toml`. Без рекламы, аналитики, Firebase.

## 3. Экраны и функции

### 3.1 Подключение

Поля: URL (`https://домен/webdav/`), логин, пароль, чекбокс «Разрешить HTTP (небезопасно)»,
по умолчанию выключен.

- «Проверить соединение» — `PROPFIND` корня. Результат с понятным текстом: успех, 401, 403,
  таймаут, ошибка SSL, неверный URL.
- Нет сохранённых настроек — стартовый экран это экран подключения.
- В приложении нет других настроек, кроме раздела синхронизации (3.3).

### 3.2 Файловый менеджер

- Список: иконка или превью, имя, размер, дата. Папки сверху. Хлебные крошки, «Назад» по иерархии,
  pull-to-refresh.
- Сортировка: имя, дата, размер, по возрастанию и убыванию.
- Создать папку (FAB).
- Загрузить файлы с телефона: `ACTION_OPEN_DOCUMENT`, multiple. Прогресс и уведомление.
- Мультивыбор (долгое нажатие) и контекстное меню: переименовать (`MOVE`), переместить, копировать,
  удалить (с подтверждением), скачать.
- Переместить и копировать: экран выбора папки назначения (тот же браузер в режиме выбора,
  кнопка «Сюда», можно создать папку).
- Скачать: в `Загрузки/FamilyCloud` через MediaStore.
- Открытие: картинка — встроенный просмотрщик со свайпом по папке и zoom; видео — встроенный плеер
  со стримингом; остальное — скачать в кэш и открыть через `FileProvider` и `ACTION_VIEW`.
- Превью картинок в списке: сервер превью не отдаёт, поэтому грузить оригинал с downsampling,
  кэш на диск, не более 3 параллельных загрузок.
- Ошибки: нет сети, 401, 403, 404, 409, 423, 507 — понятные сообщения и «Повторить».

### 3.3 Синхронизация альбомов

- Список пар «альбом телефона → папка на сервере». Пар может быть несколько.
- Добавление: альбом из MediaStore (`BUCKET_DISPLAY_NAME`) и папка сервера через браузер из 3.2.
- Параметры пары: фото вкл/выкл, видео вкл/выкл, только Wi-Fi (по умолчанию вкл),
  только при зарядке (по умолчанию выкл), пара включена/выключена,
  «Только новые, начиная с сегодня» (по умолчанию выкл — выгружается весь альбом).
- Режим: **только выгрузка** телефон → сервер. Удаления не синхронизируются.
- Что выгружать: таблица Room `uploaded(pairId, mediaStoreId, remotePath, size, dateModified)`.
  Выгружается, если записи нет или изменились size/dateModified.
- Имя на сервере: исходное имя файла, плоско, в папку пары. Если имя занято (`PROPFIND`) и размер
  совпал — считать выгруженным, пропустить. Если размер другой — добавить суффикс ` (1)`, ` (2)`.
- Надёжность: `PUT` потоком из `ContentResolver`, без чтения файла в память. Сначала `имя.part`,
  затем `MOVE` в финальное имя. Один файл за раз. Таймаут чтения/записи 5 минут. Ретраи с backoff.
  При старте синхронизации удалять только свои «осиротевшие» `.part` из записей Room.
- Запуск: периодический (15 минут) с ограничениями по сети/зарядке; триггер по новым медиа
  (`ContentUriTrigger`); кнопка «Синхронизировать сейчас».
- Долгие выгрузки — foreground worker (`setForeground`, тип `dataSync`) с уведомлением
  «Выгружено 12 из 87», прогресс, кнопка «Отмена».
- Статус на экране: последняя синхронизация, число ожидающих файлов, ошибки с «Повторить».
- Разрешения: `READ_MEDIA_IMAGES`, `READ_MEDIA_VIDEO` (API 33+), `READ_EXTERNAL_STORAGE` (≤32),
  `ACCESS_MEDIA_LOCATION`, `POST_NOTIFICATIONS`. Частичный доступ к медиа (Android 14+) — показать
  предупреждение, что синхронизируются только выбранные файлы. Подсказка про оптимизацию батареи.

## 4. Нефункциональные требования

- Единственный сетевой адрес — WebDAV пользователя.
- Пароль не попадает в логи; логирование OkHttp выключено в release.
- Тёмная тема, Dynamic Color. Поворот экрана без потери состояния и падений.
- Корректное кодирование путей (пробелы, кириллица, `#`, `%`, `+`) и разбор `href` из PROPFIND
  (абсолютные и относительные, с префиксом `/webdav/`, с завершающим `/` у папок).
- Размеры — `Long` (файлы больше 4 ГБ). Пустые папки, длинные имена — без падений.
- Особенности сервера Keenetic (какие методы и заголовки он поддерживает, лимиты на размер файла,
  поведение `MOVE`/`COPY`, `Overwrite`) **не предполагай — проверь на реальном сервере** на этапе M2
  и зафиксируй находки в `docs/SERVER_NOTES.md`.

## 6. Тесты (обязательно)

- Парсер PROPFIND: разные форматы `href`, namespace-префиксы (`D:`, `d:`, без префикса),
  папки и файлы, пустой ответ, кириллица и пробелы.
- Построение URL и кодирование/декодирование путей.
- Логика «что выгружать» и выбор имени при конфликте — на фейковых данных.
- WebDAV-клиент — на `MockWebServer` (OkHttp): статусы 207, 401, 404, 405, 409, 507.

## 7. GitHub Actions

Файл `.github/workflows/build.yml`:

- Триггеры: push в `main`, pull request, тег `v*`, `workflow_dispatch`.
- JDK 17, `gradle/actions/setup-gradle` (кэш).
- Шаги: `./gradlew testDebugUnitTest assembleDebug`; если заданы секреты подписи —
  ещё `assembleRelease`. Загрузка APK через `actions/upload-artifact`.
- Секреты подписи: `KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`.
  Workflow декодирует keystore во временный файл, который не попадает в артефакты и логи.
  Нет секретов (форк, PR из форка) — собирается только debug-APK, workflow не падает.
- Тег `v*`: GitHub Release с подписанным APK (`softprops/action-gh-release`).
- Release: R8 включён. Если ломает работу — keep-правила, а не отключение, кроме крайнего случая
  (тогда запиши причину в README).
- Права workflow минимальные (`permissions: contents: read`; для release — `contents: write` только в job релиза).
- README: как сгенерировать keystore (`keytool`), как закодировать в base64 и добавить секреты.
  Предупредить, что потеря keystore = невозможность обновлять приложение.

## 10. Критерии приёмки

1. Репозиторий собирается в GitHub Actions без ручных действий; APK доступен в артефактах и в Release по тегу.
2. После ввода URL/логина/пароля «Проверить соединение» проходит, в списке видны файлы сервера.
3. Работают создание папки, загрузка, переименование, перемещение, копирование, удаление, скачивание.
   Результат виден на сервере.
4. Фото открываются во встроенном просмотрщике, видео воспроизводится.
5. Для альбома Camera создана пара. Новое фото появляется на сервере в течение ~15 минут без открытия
   приложения. Повторный запуск не создаёт дублей.
6. Выгрузка видео ≥1 ГБ не падает по памяти и переживает кратковременную потерю сети: дозагрузка без
   дублей и без «мусорных» `.part` на сервере.
7. Пароль нигде не виден в логах, коммитах и артефактах CI.
