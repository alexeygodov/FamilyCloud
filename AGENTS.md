# FamilyCloud Android — точка входа для агента

Android-клиент WebDAV (роутер Keenetic KN-1010, KeeneticOS 5.0): файловый менеджер
в стиле Яндекс/Google Диска и выгрузка альбомов телефона в папки на сервере.

**Сначала прочитай `SPEC.md` целиком.** Это единственный источник требований.
Здесь — правила работы. Если `SPEC.md` и этот файл расходятся, спроси пользователя.

## Статус

Реализован клиент по SPEC.md: подключение, файловый менеджер, просмотр фото и видео, синхронизация альбомов. Репозиторий: https://github.com/alexeygodov/FamilyCloud
CI зелёный: https://github.com/alexeygodov/FamilyCloud/actions/runs/42799437472
На релизе есть debug и подписанный release APK: https://github.com/alexeygodov/FamilyCloud/releases/tag/latest
Локально проверены юнит-тесты и подпись release (v2 и v3). Телефон и роутер Keenetic не проверялись — список в `docs/SERVER_NOTES.md`.

## Область работ

- Работай только внутри `cloud-app/`. Каталог `../vpn/` — другой проект, не трогай.
- `cloud-app/` должен жить **отдельным git-репозиторием** (корень репозитория = эта папка).
  Причина: `.github/workflows` работает только из корня репозитория, а в `../vpn/` лежат
  сертификаты и ключи, которые нельзя публиковать вместе с приложением.
- Если репозитория нет, предложи пользователю создать его (скилл `new-repo` или `gh repo create`).
  Ничего не пушь и не создавай публичные репозитории без явного согласия.

## Жёсткие правила

1. **Стек зафиксирован**: Kotlin, Jetpack Compose, Material 3, Room, DataStore, WorkManager,
   OkHttp, Coil, Media3. WebDAV-клиент пиши сам поверх OkHttp. Без Sardine, Firebase,
   аналитики, рекламы и других сетевых адресов, кроме WebDAV пользователя.
2. **Секреты**: пароль WebDAV, keystore и его пароли не попадают в код, логи, коммиты, тесты и README.
   В тестах и примерах — только вымышленные значения (`https://example.keenetic.link/webdav/`).
3. **Нельзя говорить «работает», пока не зелёный CI** (или локальная сборка, если есть SDK).
   Фиксируй, что именно проверено: юнит-тесты, сборка APK, ручная проверка на устройстве.
   Ручные сценарии на телефоне и роутере ты проверить не можешь — перечисли их пользователю.
4. **Зависимости**: добавляй только через `gradle/libs.versions.toml` (version catalog), актуальные
   стабильные версии. Не угадывай номера — проверь на Maven Central/Google Maven или через веб-поиск.
5. **Не расширяй объём**: пункты из раздела «Вне рамок» `SPEC.md` не делать, даже если «просто».
6. **Данные пользователя**: синхронизация только выгружает. Никогда не удаляй и не изменяй
   файлы на телефоне и не удаляй на сервере ничего, что не создано действием пользователя в UI.
7. **Один этап — один набор коммитов с зелёным CI.** Не начинай следующий этап при красном CI.
8. Коммиты маленькие, сообщения по-английски в повелительном наклонении
   (`Add PROPFIND parser`). Не коммить `*.jks`, `*.keystore`, `local.properties`, `build/`.

## Навыки и инструменты

Android-специфичных скиллов в Cursor нет, ставить отдельные «Android skills» не нужно.
Используй такие:

| Что | Зачем | Когда |
|---|---|---|
| Скилл `new-repo` / `share` | создать репозиторий и запушить | M0, после согласия пользователя |
| Скилл `autopilot` | довести PR/ветку до зелёного CI | после каждого этапа |
| Скилл `review-bugbot` | ревью диффа | перед закрытием M2, M4, M5 |
| Скилл `review-security` | ревью работы с секретами, подписью, HTTP | перед закрытием M1 и M5 |
| Скилл `split-to-prs` | разбить большой дифф на PR | если дифф этапа большой |
| `gh` CLI | читать статус и логи GitHub Actions | M0 и дальше. **Сейчас не установлен**: `winget install GitHub.cli`, затем `gh auth login` |
| JDK 17 | локальная сборка и тесты | `java` есть, проверь версию (`java -version` должен быть 17+) |
| Android SDK + Gradle | локальная сборка | **Не установлены.** Не обязательно: сборку делает CI. Если нужна локальная — `winget install Google.AndroidStudio` или cmdline-tools, затем `ANDROID_HOME` |
| MCP Context7 (по желанию) | актуальная документация Compose, Media3, WorkManager | если пользователь подключит; иначе веб-поиск |

Gradle wrapper: если `gradle` не установлен, получи wrapper одним из способов — скачай дистрибутив
Gradle (zip) и выполни `gradle wrapper --gradle-version <актуальная стабильная>`, либо
`winget install Gradle.Gradle`. Закоммить `gradlew`, `gradlew.bat`, `gradle/wrapper/*`.

## Порядок работы агента

1. Прочитай `SPEC.md`. Составь список задач текущего этапа (TodoWrite).
2. Реализуй этап, добавь тесты, указанные в `SPEC.md`.
3. Запусти сборку и тесты (CI или локально), исправь ошибки.
4. Кратко отчитайся: что сделано, что проверено, что пользователю проверить руками.
5. Дождись подтверждения перед следующим этапом, если этап требует ручной проверки
   (M2, M4 — нужен реальный WebDAV и телефон).

## Что нужно от пользователя (не придумывай сам)

- Решение о репозитории GitHub (название, приватный/публичный).
- Keystore для release-подписи: пользователь генерирует его сам по инструкции из README
  и кладёт в GitHub Secrets. Ты секреты не создаёшь и не видишь.
- Тестовый WebDAV: адрес, логин, пароль для ручной проверки. Попроси завести отдельного
  пользователя роутера и тестовую папку.
